# Source Index

This index describes the source files copied into `Canonical-Documents/`. Exact version authority must be assessed from document content and approvals, not filename recency alone. Hashes in `Source-Checksums.txt` help verify that the archived copies have not changed.

| Source group | Archived location | Use / caveat |
|---|---|---|
| SRS versions | `Canonical-Documents/Requirements/` | Requirements intent; multiple versions exist. Cross-check; not proof of implementation. |
| Project plans | `Canonical-Documents/Plans/` | Timeline and deliverables; confirm actual progress. |
| Letter of Agreement | `Canonical-Documents/Agreements/` | Contractual source; support-duration wording needs alignment. |
| Technical documentation | `Canonical-Documents/Technical/` | Proposed architecture and implementation notes; validate against actual repository. |
| SWOT | `Canonical-Documents/Planning/` | Context and team details; supporting source. |
| Feature/access-control spec | `Canonical-Documents/Working-References/` | Current working specification; intended behavior, not implementation proof. |
| README | `Canonical-Documents/Working-References/` | Current technical constraints and overview; older naming may differ. |
| HTML prototypes | `Canonical-Documents/Design-and-Prototype/` | Mock data and UI intent only. |
| UI blueprint/spec ZIPs | `Canonical-Documents/Design-and-Prototype/` | Earlier candidate design packages; preserve intact and reconcile differences. |
| Updated document pack ZIP | `Canonical-Documents/Packages/` | Archive intact; includes a set of updated DOCX documents. |
