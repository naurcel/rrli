## Executive Summary

The RouteX Import feature has been redesigned, hardened, and moved into a dedicated, full-screen workflow at `/deliveries/import`. Previously, the import mechanism suffered from naive string splitting, missing delimiter negotiation, lack of multi-stop aggregation, hardcoded fallback mutations (which silently invented waybill numbers, rates, and dates), and lack of client-side cache synchronization.

The new implementation delivers a **4-step guided import pipeline** strictly aligned with RouteX design principles (Readex Pro typography, minimal plain-text status indicators, subtle neumorphic surfaces, zero unnecessary button shadows). It supports standard RFC 4180 delimited files (CSV, TSV, DSV) generated by Microsoft Excel and Google Sheets, aggregates multi-stop drop-offs by waybill number, provides live inline validation and editing, enforces strict duplicate detection, persists records to server and local storage, and logs all batch operations to the immutable audit ledger.

---

## 1. How the Original Import Feature Worked

Before this implementation, the import system was evaluated across both the UI and backend:

1. **Popup / Fragile Client (`src/components/delivery-import-client.tsx`):**
   - The original component attempted to parse CSVs using raw `.split(",")` and line-splitting. This broke when cells contained escaped quotes, embedded commas (such as `"Landers Superstore, Balintawak"`), or newlines.
   - It silently invented missing data: if a waybill number was absent, it generated `WB-${Date.now().toString().slice(-6)}`; if client name was missing, it hardcoded `"Landers"`; if revenue was missing, it injected `20000`; if diesel was absent, it defaulted to `3500`.
   - It treated each row in the spreadsheet as an isolated delivery. In real logistics operations, Daily Trip Reports (DTRs) list a row for each store drop-off under the same waybill number. As a result, multi-stop trips either produced duplicates or overwrote one another.
   - It lacked integration with `upsertBrowserPreviewDelivery`, meaning successfully imported trips did not reactively appear on `/deliveries` or `/dashboard` without manual refreshes.

2. **Backend API (`src/app/api/deliveries/import/route.ts`):**
   - The backend enforced Zod validation and checked permissions, but did not persist new records to `.mock-storage.json` via `savePersistedMockDeliveries()`.
   - Driver and helper names present in the spreadsheet were ignored or replaced with static fallback IDs.
   - The route did not return the created `DeliveryLedgerItem` entities to the client, preventing real-time state synchronization.

## 2. Supported Data Types & File Formats

### Supported File Formats
- **Delimited Text:** `.csv` (Comma-Separated), `.tsv` (Tab-Separated), and `.txt` (Pipe/Semicolon-Separated).
- **Encoding:** UTF-8, UTF-8 with BOM (Byte Order Mark stripped automatically).
- **Standards Compliance:** Strict RFC 4180 parsing for quoted cells, internal commas, escaped double-quotes (`""`), and CRLF/LF newlines.
- **Maximum File Size:** 10 MB per upload.

### Supported Fields & Column Synonym Mapping
The parser automatically detects and normalizes spreadsheet headers regardless of naming variations:

| Target Operational Field | Accepted Column Synonyms | Format / Rules |
| :--- | :--- | :--- |
| **Waybill Number** | `waybill`, `wb_no`, `waybill_number`, `tracking` | Required, string ≥ 3 chars, case-insensitive duplicate check |
| **Delivery Date** | `date`, `delivery_date`, `trip_date` | Required, `YYYY-MM-DD`, must be ≥ `2024-01-01` (foundation year) |
| **Client Name** | `client`, `customer`, `account`, `client_name` | Required, string ≥ 2 chars; resolves to registered or dynamic client |
| **Plate Number** | `plate`, `truck`, `truck_plate`, `vehicle` | Required; matches registered fleet trucks |
| **Truck Temperature** | `temperature`, `temp`, `reefer_temp` | Validates numeric value in `°C` (e.g. `-18°C`, `4°C`, `20°C`) |
| **Origin Hub** | `origin`, `depot`, `hub`, `dispatch` | Defaults to `"Central Depot"` |
| **Delivery Rate (Revenue)** | `rate`, `revenue`, `delivery_rate`, `earnings` | Required numeric > 0; strictly non-zero |
| **Diesel Expenses** | `diesel`, `fuel`, `diesel_expenses` | Numeric ≥ 0 or empty (`null` / unconfirmed) |
| **Highway Tolls** | `toll`, `tolls`, `toll_gate_expenses` | Numeric ≥ 0 or empty (`null`) |
| **Driver Name** | `driver`, `driver_name`, `operator` | String; matches registered crew member |
| **Helper Name** | `helper`, `helper_name`, `crew` | String; matches registered crew member |
| **Store Name** | `store`, `store_name`, `destination_store` | Required for drop-off stop |
| **Destination Area** | `area`, `destination_area`, `city`, `location` | Required for drop-off stop |
| **Store Entry Fee** | `entry_fee`, `fee`, `store_fee`, `parking` | Numeric ≥ 0 or empty (`null`) |

## 3. Functionality Implemented & Repaired

### A. Dedicated Multi-Step Import Page
- Accessible directly from `/deliveries` via the top action button.
- Enforces server-side RBAC: restricted exclusively to authorized roles (`canImportAndReviewExcel` / `imports:upload` for Admin and Operations).
- Clean 4-step wizard:
  1. **Select File:** Drag-and-drop zone, template downloader, sample data loader, and batch name configuration.
  2. **Preview & Validate:** Interactive staging table with validation tabs, real-time search, inline cell editing, and row deletion.
  3. **Confirm Batch:** Clear pre-commit summary highlighting ready trips, duplicates to skip, and excluded rows.
  4. **Import Results:** Success metrics, committed waybill chips, audit download button, and direct navigation links.

### B. High-Fidelity Delimited Parser (`delivery-import-parser.ts`)
- Custom state-machine tokenizer (`parseDelimitedText`) handling arbitrary delimiters, quotes, and multiline text cells without external bloated dependencies.
- **Multi-Stop Trip Grouping:** Automatically groups multiple CSV rows that share the same waybill number into a single delivery trip containing multiple sequential drop-offs.
- Header synonym resolver matching 25+ common spreadsheet header variants.
- Strict data integrity: missing rates or dates never receive fabricated placeholder values.

### C. Live Interactive Validation & Staging
- Every staged row tracks `status: "ready" | "needs_attention" | "duplicate"` and an array of specific field issues.
- Modifying a field inline immediately re-runs `validateStagedRow` against existing waybills and updates the row status and tab counters reactively.
- Status tabs allow one-click filtering to isolate records requiring attention before confirmation.

### D. Server Endpoint & Dual Storage Persistence (`/api/deliveries/import`)
- Validates batch payload using Zod.
- Resolves fleet trucks from `truck-registry.ts` and drivers/helpers from `driver-registry.ts`.
- Persists mock deliveries to `.mock-storage.json` via `savePersistedMockDeliveries()`.
- Emits created `DeliveryLedgerItem` records back to the browser client, which immediately invokes `upsertBrowserPreviewDelivery` and dispatches `BROWSER_PREVIEW_DELIVERIES_CHANGED`.
- Records detailed batch import events in the RouteX audit log.

## 4. Validation, Duplicate Handling, and Error Reports

1. **Pre-Import Duplicate Detection:**
   - On load, the client retrieves existing waybill numbers from both local browser storage (`readBrowserPreviewDeliveries()`) and the server (`/api/deliveries`).
   - Any uploaded waybill already recorded in the system is automatically categorized as `duplicate` (Skip).
   - In-file duplicates (identical waybill numbers across separate trips) are identified and reconciled into multi-stop stops or flagged.

2. **Validation Rules Enforced:**
   - `waybillNumber`: Non-empty string (min 3 characters).
   - `deliveryDate`: Valid ISO date, strictly on or after `2024-01-01` (foundation boundary).
   - `deliveryRate`: Strictly positive number (`> 0`). Missing rate is flagged as an error and never coerced to 0.
   - `truckTemperature`: Validated format (e.g. `-18°C`).
   - `clientName` & `plateNumber`: Required non-empty strings.
   - `dropoffs`: At least one store destination required per waybill.

3. **Audit & Error Report Generation:**
   - If an import contains duplicates or errors, users can click **Download Audit / Error Report (CSV)**.
   - The generated CSV itemizes every row with its waybill, date, client, plate, status (`COMMITTED`, `DUPLICATE_SKIPPED`, `VALIDATION_FAILED`), and exact diagnostic messages.

## 5. Security Safeguards & RBAC Enforcement

- **Server-Side Page Guard:** `src/app/(workspace)/deliveries/import/page.tsx` checks `canImportAndReviewExcel(actor.role)`. Non-operations/non-admin roles are redirected with `access=restricted`.
- **API Guard:** `POST /api/deliveries/import` calls `verifyServerPermission("imports:upload")`. Requests lacking authorization receive `403 Forbidden`.
- **Idempotency Protection:** Every batch submission generates a UUID `idempotencyKey` preventing duplicate database commits upon repeated network requests.
- **Audit Logging:** Every committed batch logs an immutable audit event (`delivery.batch_imported`) detailing the user, batch name, total rows, committed waybill numbers, and skipped count.

## 7. Remaining Limitations & Future Considerations

1. **Native Binary `.xlsx` Files:** The current parser natively parses delimited text files (`.csv`, `.tsv`, `.txt`). Spreadsheets must be saved or exported as CSV/TSV from Excel. If direct `.xlsx` binary parsing is desired in the future, a streaming library (such as `exceljs`) can be added without changing the 4-step UI workflow.
2. **Custom Column Drag-and-Drop Mapping:** While the current parser includes an extensive synonym table covering 25+ variations, future versions could provide a visual column-mapping step if external clients provide non-standard DTR schemas.
3. **POD Document Attachment via Import:** Imported trips are marked as `"Awaiting POD upload"`. Bulk uploading ZIP archives of signed POD images matched by waybill number can be implemented as an enhancement to the POD Documents module.
